# CTE 常见支持流程

这些流程来自 CTE 培训材料中的稳定排障模式。产品价格、降级周期、退款、活动和负责人会变化，不在 skill 中固化；遇到此类问题时以当前正式政策和团队通知为准。

## 标准服务定位链路

1. 从工单确认手机号或邮箱及具体症状，并确认可将该标识提交到内部 Grafana。
2. 按 SKILL.md 的 Grafana 浏览器查询协议：Agent 用浏览器工具登录 Grafana Explore，直接执行最小字段查询，取得 Pool ID、组织 ID、订阅状态和必要的 endpoint host。
3. 检查订阅状态：`active` 通常表示有效，`suspended` 表示需先核对续费或账户状态；不要因为服务暂时仍可访问就忽略 suspended。
4. 如确需验证原生页面，由操作员在浏览器中打开已授权 endpoint；完整 URL 可能包含 Gateway Token，不得在报告、聊天或日志中回显，也不要尝试让 Agent 打开。
5. 在 Rancher/Kubernetes 按 `moltbot-<pool-id>-` 定位 Deployment/Pod；跨集群搜索仅限已有 RBAC 的已知 OpenClaw 命名空间。
6. 比对 Ingress host 与 Grafana endpoint host，并检查 Service、EndpointSlice、Pod Ready、探针、事件和日志。

解释结果：

- 原生页面能打开且 WebSocket/会话连接成功：入口和 Gateway 基本正常，继续调查 Agent、模型或配置层。
- `no healthy upstream`：优先检查 Ready、EndpointSlice、探针和应用端口，不要直接假设网络故障。
- Deployment 存在但副本数为 0：记录为 scale-to-zero/降级状态，确认当前策略及授权后再恢复副本。
- Deployment、Pod、Service、Ingress 均不存在：可能已删除或迁移；不要自行重建，联系平台负责人确认目标集群和恢复流程。

## 对话无响应

按顺序区分：

1. 页面连接与 WebSocket；
2. Pod Ready、Gateway `ready`、18789 等健康端口；
3. 上游模型请求错误；
4. API Key/组织/余额；
5. Agent 或配置文件错误。

`LLM request failed` 或 network error 需要与 DNS、出口连接、上游延迟及同时间 Pod 日志关联。只有网络异常证据充分且用户明确授权后，才执行一次 Redeploy；重建后必须验证 Ready、重启数和相同请求。不要用“多试几次 redeploy”替代诊断。

## 401/403 认证问题

- 先确认用户选择了有余额的组织，并由用户在自己的用户中心核对或重新配置 API Key/Gateway Token。
- 只读检查可以确认字段是否为空、占位符或配置来源，但不得读取、复制或回显完整 Key/Token。
- 修改配置、替换 Token 或重启服务属于生产变更，必须说明影响、备份/回滚方法并取得明确授权。
- 如果配置文件中仍是占位符，指导用户自行提供合法配置，不要从其他用户或环境复制密钥。

## 400 Bad Request

从同一请求时间附近的日志区分：

- `openclaw.json` JSON 语法或字段格式错误；
- 模型名称不存在或拼写错误；
- 请求体或附件超过限制；
- 上游返回的其他参数错误。

不要在没有日志证据时直接改配置。修复前备份配置，修复后做 JSON 解析检查并验证一次请求。

## PVC 配额或 I/O 故障

常见信号包括 `Unknown system error -122`、`EDQUOT`、`disk quota exceeded`、`disk I/O error`、扩展或状态数据库无法写入，以及探针随之失败。

只读检查：

1. 确认 PVC/PV、容量、StorageClass、访问模式和回收策略；
2. 若用户明确授权容器内盘点，只统计 `/home/node` 下目录大小、inode 和大文件元数据，不读取文件内容；
3. 共享 NAS 的 `df` 可能显示后端总量，以目标目录 `du` 和平台侧配额为准；
4. 区分可重建缓存、安装运行库、OpenClaw 配置、会话和客户文件。

删除、替换镜像或扩容前必须取得精确授权：目标集群、Pod/PVC、绝对路径或容量均需明确。不得默认删除 `/home/node`、`.openclaw`、workspace、配置、会话或客户上传文件。

当容器无法稳定运行且确实需要临时 debug 镜像时，将其作为高级升级方案：记录原镜像、确认 debug 镜像来源、说明服务会中断、取得授权、只清理批准的路径，然后恢复原镜像并验证。不要把替换镜像作为常规第一步。

## 对话记录或文件“消失”

- 文件通常位于 PVC 挂载的 workspace；对话历史通常位于 `.openclaw/agents/<agent>/sessions/*.jsonl`。
- 前端未显示不等于底层文件不存在。先检查 PVC 挂载、文件元数据和应用索引/会话日志。
- 不读取会话正文，除非内容对诊断必要且获得单独授权。
- PVC 数据通常跨 Pod 重建保留，但手工删除、应用重置、PVC 删除或存储故障仍可造成丢失；不要向用户做绝对保证。

## 余额、充值与消纳

- 先查组织 ID，再查非 deduction 的余额变更或指定 UTC 时间段的 usage 聚合。
- 充值记录存在但当前组织余额不足时，提示核对用户当前选择的组织；不要自动创建或迁移 API Key。
- 消纳数据可能存在处理延迟。培训材料记录的经验值约为 1 小时，但应标注为经验信息并结合最新数据更新时间验证。
- `output_tokens = 0`、多模型或高输入 token 只是线索，需要结合状态、费用规则和应用日志判断。

## 内部结论与对客说明

报告分成两个字段：

- `内部排查结论`：允许包含集群、Pod、日志模式和执行过的变更；
- `建议对客回复`：只包含用户需要知道的影响、当前状态和下一步，不暴露内部拓扑、凭据、安全配置或未经确认的根因。

如果没有明确的对客内容，使用中性表述，例如请用户重试并在仍有问题时反馈时间点和截图，不要把内部技术结论原样发送给用户。
